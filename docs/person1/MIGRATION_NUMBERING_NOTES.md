# 마이그레이션 번호 변경 메모 (팀장 공유용)

## 무슨 일이 있었나

티켓 1-1("채널 진단 도메인 모델") 원문은 `0034, 0035, 0036` 세 번호를 **1-1 자신이 만드는 테이블 3개**(`tracked_channels`/`channel_diagnoses`/`marketing_metric_snapshots`)에 쓰도록 되어 있었습니다. 그런데 백로그 상에서는 `0035`가 **1-6**(스냅샷 수집 파이프라인), `0036`이 **1-8**용으로 이미 따로 예약되어 있었던 것으로 보입니다.

1-1을 그 원문대로 구현하면서 `0034~0036`을 전부 1-1이 소비했기 때문에, **1-6과 1-8이 실제로 마이그레이션을 작성할 시점에는 `0035`/`0036`을 쓸 수 없고 그다음 빈 번호(현재 기준 `0037` 이상)를 써야 합니다.**

## 실제로 적용된 내용 (main에 커밋됨: `0c42e92`)

- `0034_tracked_channels.sql`
- `0035_channel_diagnoses.sql`
- `0036_marketing_metric_snapshots.sql`

전부 1-1 소관이고, 각 티켓이 원래 기대했던 테이블과는 무관합니다.

## 앞으로의 규칙

1-6, 1-8을 포함해 앞으로 어떤 티켓도 **원문에 적힌 마이그레이션 번호를 그대로 믿지 않습니다.** 새 마이그레이션 파일을 작성하기 직전에:

```bash
ls supabase/migrations | sort -V | tail -5
```

로 현재 main(과 작업 브랜치)의 실제 최댓값을 확인하고, 그다음 빈 번호를 씁니다. 번호가 티켓 원문과 달라지면 이 문서에 한 줄 추가합니다.

| 티켓 | 원문이 예상한 번호 | 실제 사용한 번호 | 비고 |
|---|---|---|---|
| 1-1 | 0034, 0035, 0036 | 0034, 0035, 0036 | 원문 그대로 적용 (테이블 3개를 1-1 자신이 소유) |
| 1-6 | 0035 (추정) | *(미정 — 구현 시점에 확인)* | 1-1이 0035를 먼저 씀 |
| 1-8 | 0036 (추정) | *(미정 — 구현 시점에 확인)* | 1-1이 0036을 먼저 씀 |
