## 직접 확인한 항목 (VERIFIED)

- 가입 → 체험 이용권(블로그 1·숏폼 1, 1회만) → 사업체/홍보 유형 → 홈페이지 진단 → 블로그 생성 → 이용권 차감 → 0개일 때 거절.
- 모의 결제(BILLING_PROVIDER=mock): 구매 → 완료 처리 → 이용권 5회 지급·만료일 30일 표시. 실제 청구 없음 문구 유지.
- 이용권 원장: 동시 예약, run-id 멱등, 실패 시 해제, 만료 순서 소진, 환불, 원장 불변 — `npm run test:credits-db` PASS.
- RLS: 모든 테이블 RLS 사용, 관리자 라우트는 비관리자에게 404, 문의/환불/관리자 DB 테스트 PASS.
- 모바일 폭(375px) 가로 스크롤 없음: dashboard, billing, calendar, support, usage, diagnosis.
- 이전 오류("일정을 불러오지 못했어요", "대시보드를 불러오지 못했습니다", "문의 기능을 준비하는 중이에요")는 새 DB에서 재현되지 않음. 마이그레이션 미적용 DB에서는 "준비 중" 안내로 낮춰 보여준다.

## 남은 위험 / 사용자 확인 필요

- 운영 DB는 0034–0071이 미적용일 수 있다 → `npx supabase db push --linked --dry-run` 후 `--linked`.
- 운영 숏폼: 실제 렌더러 설정 전에는 의도적으로 거절된다(샘플 영상 보호).
- 환불: 가맹 카드 취소는 Toss 테스트 키가 있어야 실제로 확인 가능 (F-011 참고).
- 요청마다 `profiles.account_status` 조회가 미들웨어와 레이아웃에서 중복된다(성능, P2). 실측 후 정리 권장.
